1. Arsitektur & Hubungan Antar-Komponen Sistem

Bagaimana Web dan Android Saling Berkomunikasi?
Sistem ini tidak menggunakan server socket mandiri, melainkan bertumpu pada Cloud Firestore sebagai event broker realtime:
  1. Pelanggan Web (Laravel): Mengirimkan data formulir pesanan melalui HTTP POST. Controller Laravel memformat dokumen NoSQL dan memanggil FirestoreService->createOrder() via Google Cloud REST API v1. Dokumen masuk ke koleksi /orders dengan field status: "PENDING" dan source: "CUSTOMER_WEB".
  2. Android Gateway (MainActivity): Memasang addSnapshotListener pada koleksi /orders dengan filter status PENDING. Saat dokumen web masuk, event DocumentChange.Type.ADDED terpicu secara instan (sub-second), membunyikan alarm bel lewat SoundHelper dan menampilkan dialog konfirmasi di layar kasir.
  3. Dapur KDS (AntrianFragment): Kru dapur memproses pesanan dengan mengubah status ke PREPARING. Halaman web pelanggan yang sedang memantau secara berkala (polling API status) mendeteksi perubahan ini dan memperbarui indikator visual di browser pelanggan secara live.
  4. Serah Terima & Pengambilan (QRScanActivity): Kasir memindai QR Code di layar pelanggan dengan kamera HP. Status pesanan diubah ke COMPLETED di Firestore, dan seluruh rincian transaksi otomatis disimpan permanen ke dalam tabel SQLite lokal riwayat_transaksi via DBOpenHelper sebagai arsip offline.
